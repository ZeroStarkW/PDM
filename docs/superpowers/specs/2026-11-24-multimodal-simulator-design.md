# 多模态设备模拟器设计

## 意图

在现有旋转设备仿真仪表盘中加入 MCSA 电机、高压断路器和工艺调节阀模拟，并通过平台现有 MQTT 遥测入口把特征送入预测链路。用户可在同一仪表盘切换各设备的健康/故障状态并查看最新遥测。现有旋转设备模拟、旧 v1 兼容发布和原始波形流程保持可用。

## 目标

- 同一 Flask 进程和现有 MQTT 客户端管理所有模拟设备。
- 新增 MCSA（`MOTOR_M01 / CH_STATOR_CURRENT`）、断路器（已有 `BREAKER_10KV_02 / CH_TRIP_UNIT`）和调节阀（已有 `FEED_VALVE_FCV101 / CH_VALVE_LOOP`）的实时数据与独立状态控制。
- 使用平台已支持的 2.1.0 `phm/telemetry/{asset_id}/{channel_id}` 契约；让数据通过 MQTT consumer、模态插件、基线/健康评分、趋势与工作台展示流程。
- 演示资产种子补齐 MCSA 电机和测点，并提供与健康模拟值匹配的 ACTIVE 基线，使首次启动无需长时间等待学习期。
- 为多模态演示设备分配独立设备类型：`ELECTRIC_MOTOR`（电动机）、`CIRCUIT_BREAKER`（高压断路器）、`CONTROL_VALVE`（调节阀）；测点模态仍各自负责遥测路由。
- 在仪表盘展示每台设备的模态、模拟状态、主要指标和 MQTT 发布状态。

## 非目标

- 不更改生产级诊断阈值、MCSA 默认告警关闭设置、评分算法或预测内核。
- 不替代现场传感器/边缘特征提取；MCSA 只合成平台接受的电流频谱特征。
- 不改变旋转振动遥测、旧 v1 主题、波形快照和专家召唤流程。
- 不新增独立服务、容器或外部依赖。
- 不把设备类型分类与测点模态合并；设备类型描述实体类别，模态控制遥测预测路由。

## 设备模拟行为

- **MCSA 电机**：稳态 50 Hz、约 1500 RPM、75% 负载；健康/转子导条故障状态改变 `sideband_amp_db`，并发布 `mains_freq_hz`、`slip_pct`、`carrier_amp_db`。工况保持稳态且负载在平台门禁范围内。
- **高压断路器**：健康/慢分闸/线圈电流偏弱状态合成 `trip_duration_ms`、`peak_coil_current_a`、`closing_velocity_mps`、`contact_wear_ratio`。按演示节奏约每 10 秒生成一次分闸事件，仪表盘提供立即触发动作；仅在动作时发布遥测，并同时发布一条匹配的 `TRIP_ACTION_BURST` 快照，不发送周期心跳。事件按现有设计保持稳态。
- **调节阀**：持续生成开度指令与反馈回环，并合成 `hysteresis_deadband_pct`、`travel_time_lag_ms`、`ultrasonic_leak_rms`、`friction_force_kn`。健康/卡涩/泄漏状态下每秒发布稳态过程量，支持专用阀工作台回环图和评分。
- 各模态的模拟状态独立；健康数值围绕演示资产基线轻微波动，故障值改变对应机理特征。所有时间戳使用毫秒 UTC，数值为有限值。

## MQTT 与预测链路

使用现有 MQTT 连接发布协议 2.1.0 遥测到 `phm/telemetry/MOTOR_M01/CH_STATOR_CURRENT`、`phm/telemetry/BREAKER_10KV_02/CH_TRIP_UNIT`、`phm/telemetry/FEED_VALVE_FCV101/CH_VALVE_LOOP`。每条载荷包含 `protocol_version`、毫秒时间戳、资产/通道 ID、模态、`data_quality=0` 和模态要求的指标。MCSA 必需 `mains_freq_hz`、`slip_pct`、`sideband_amp_db`、`carrier_amp_db`，工况提供 `steady_state=true`、`load_pct=75`（并可给 `rpm`，平台按契约从工况补入负载特征）；断路器必需 `trip_duration_ms`、`peak_coil_current_a`，可附加其它机理特征；调节阀必需 `hysteresis_deadband_pct`、`ultrasonic_leak_rms`，且工况提供 `steady_state=true`。阀门和电机每秒发布；断路器每次动作发布遥测和匹配的 `TRIP_ACTION_BURST` 曲线快照。模拟器仅发布测量特征，不自行产生 HI 或告警；平台负责评分和诊断。

为 MCSA 演示资产的 `sideband_ratio` 和 `carrier_amp_db` 建立与健康载荷一致的 ACTIVE 基线。按现有种子约定，仅补齐缺失基线特征行，不覆盖任何已存在行；已有冲突基线由用户显式重置/修正。`PDM_MCSA_ALERTS_ENABLED` 保持现状（默认 false），因此 MCSA 故障演示可影响相对健康评分/趋势，但不会开启确定性 MCSA 告警。

演示种子按编码幂等创建三种设备类别，并把对应的演示设备分配到类别；旋转泵和其它设备保留原分类。分类只影响资产类型与按设备类型配置的诊断规则，不改变测点模态。

## 仪表盘改动

保留当前旋转设备主工作区，在同一页面增加多模态设备卡片，显示当前模式与最新特征；增加每台设备独立的健康/故障选择、断路器立即动作控制和 MQTT 状态。扩展现有数据/控制 API，原有旋转控制请求不变；对新控制请求按设备编码校验允许的状态，不能因未知状态或数值输入使模拟循环崩溃。

## 方案比较与选择

1. **单进程扩展（已选）**：在现有 Flask 模拟循环和 MQTT 客户端中增加多模态模拟状态、数据生成与页面控制。沿用已有启动方式和 MQTT 连接，演示部署最简单；共享进程故障会影响全部模拟设备。
2. **独立模拟服务**：各模态单独进程，由页面控制启停与状态。故障隔离更好，但增加子进程管理、状态同步和服务生命周期复杂度，不适合当前本地 MVP。

## 约束与验收结果

- 保持 Python 项目现有运行方式和依赖；模拟器在 MQTT 未连接时仍可打开仪表盘并展示本地生成状态。
- 演示资产在 `PDM_DEMO_DATA=true` 下幂等补齐，现有资产/测点不重复创建或重写业务字段。
- 在启动模拟器与平台、启用演示资产后，三类新模态均能经 MQTT 被平台接受，并在其对应工作台中出现实时测量/评分帧；模拟器断开 MQTT 时不影响旋转设备与本地仪表盘。
- 文档说明如何启用演示数据、启动模拟器和查看各设备预测结果，并注明 MCSA 默认不生成确定性告警。

## 留给实现者

按现有 Python 单文件风格扩展还是把模拟逻辑拆到同项目内的 Python 模块，由实现者决定；HTTP 路由和页面结构也可沿用现有样式。特征键、设备/测点编码、主题、模态状态和对外行为按本文固定。
