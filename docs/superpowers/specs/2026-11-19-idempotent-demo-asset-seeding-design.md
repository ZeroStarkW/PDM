# 幂等补齐演示资产

## 意图

当 `PDM_DEMO_DATA=true` 时，即使数据库中已有 `FACT_01` 工厂或 `PUMP_P102A` 设备，也应补齐缺失的演示设备与 `DE_RADIAL` 测点，避免模拟器 MQTT topic 被拒绝为“测点不存在”。

## 目标与边界

- 分别按工厂编码、工厂下的设备编码、设备下的测点编码查找并创建缺失记录。
- 保留已有记录和配置；初始化器仍仅在演示数据开关开启时运行。
- 不为任意设备自动创建测点，不改变 MQTT 校验规则。

## 方案

- 选定：将演示数据初始化器改为逐级幂等补齐；现有工厂、设备或测点都可单独存在。
- 不选：新建设备时统一创建默认测点，因为设备可能有多种测点配置。
- 不选：未知 MQTT 遥测自动建点，因为拼错的 topic 也会被持久化为资产。

## 实施决定

仅调整 `DemoDataInitializer` 的查找与补齐流程；复用现有仓储查询和实体创建逻辑。演示资产查询与写入在同一 PostgreSQL 事务中进行，并用事务级 advisory lock 串行化并发启动。此修复部署后需开启 `PDM_DEMO_DATA=true` 并重启应用，初始化器才会补齐已有数据库中的缺项。

## 验收

已有工厂但缺设备、已有设备但缺测点、三者全缺的情况下，演示模式启动后都应得到完整的 `FACT_01 / PUMP_P102A / DE_RADIAL` 关联；已存在的记录不得重复创建或覆盖。
